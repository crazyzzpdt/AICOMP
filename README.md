1. **报名**：在系统中创建队伍、完成信息填写和缴费，下载初赛数据。

## 赛题任务

对空间对齐的三模态图像进行目标检测：

- RGB 可见光图像
- Infrared 热红外图像
- Depth 深度图像

目标是在路口、公园、室内、空中等复杂城市场景下，完成目标定位和分类。12 个英文类别的对应含义如下：

| 编号 `class_id` | 英文原词 | 中文含义 / 官方包含范围 |
|---:|---|---|
| 0 | `person` | 行人 |
| 1 | `boat` | 船 |
| 2 | `animal` | 动物 |
| 3 | `seat` | 座椅 |
| 4 | `sign` | 标识：路牌、标语、标志等 |
| 5 | `bicycle` | 双轮车：自行车、双轮电动车等 |
| 6 | `car` | 四轮汽车 |
| 7 | `ball` | 球 |
| 8 | `light` | 灯：路灯和室内照明灯 |
| 9 | `garbage can` | 垃圾箱 |
| 10 | `uav` | 无人机（Unmanned Aerial Vehicle） |
| 11 | `tricycle` | 三轮车 |

### 任务到底要做什么

**一句话版：** 主办方每次给你一组“同一场景的三张对齐图”，你要用程序在图上找出所有规定类别的物体，再为每个物体输出一个矩形框、类别编号和可信度。

这里的“空间对齐”表示：同一个人或车在 RGB、红外、深度三张图里的位置相互对应，不是三张互不相关的照片。模型需要同时利用这三份信息，找出画面中的所有目标，并为每个目标给出：

1. **类别**：属于 12 类中的哪一类。
2. **位置**：目标框在图中的中心点、宽度和高度。
3. **置信度**：模型对该预测的可信程度，取值为 0–1。

因此，最终产物不是“只说这张图里有什么”的分类标签，不是给物体逐像素涂色的分割掩码，也不是融合后的新图片；而是**每张测试图的一组检测框 TXT 文件**。

### 英文术语逐个对照

| 官网英文 | 中文解释 | 在本题里具体表示什么 |
|---|---|---|
| `RGB` | 红、绿、蓝三通道可见光图像 | 普通彩色相机图；能看颜色、纹理和外观。 |
| `Infrared` | 红外 / 热红外图像 | 热成像图；像素值越高，表示目标温度越高、画面越亮。它虽然存为三通道，但本质是同一张热度灰度图复制到三通道。 |
| `Depth` | 深度图 | 每个像素到相机的距离，单位是毫米；值越小越近，值越大越远；0 或很小值常表示无效深度。 |
| `multi-modal` | 多模态 | 同时使用 RGB、红外和深度三类不同来源的信息。 |
| `object detection` | 目标检测 | 找出“是什么”和“在哪里”，即类别 + 矩形框。 |
| `Bounding Box` | 边界框 / 检测框 | 围住一个目标的矩形框。 |
| `Class Label` | 类别标签 | 该框对应的类别，如 `person`、`car` 或 `uav`。 |
| `confidence` | 置信度 | 模型认为该框正确的程度，范围 0–1；越大越可信。 |
| `class_id` | 类别编号 | 上表中的 0–11，例如 6 就是 `car`。 |
| `norm_*` | 归一化后的比例值 | 不使用像素坐标，而使用 0–1 的比例，便于不同尺寸图像统一评测。 |
| `norm_center_x` / `norm_center_y` | 框中心点的横 / 纵坐标比例 | `0.5` 表示正好在图像宽度 / 高度的中间。 |
| `norm_w` / `norm_h` | 框宽 / 高占整图的比例 | 例如 `norm_w=0.2` 表示框宽为整张图宽的 20%。 |
| `feature fusion` | 特征融合 | 让模型综合三张图各自提取到的信息后再做检测，而不是只使用其中一张。 |

### 用一个输出例子理解

若模型在一张图里发现一辆车，生成一行：

```text
6 0.50 0.60 0.30 0.20 0.92
```

含义是：`6` = 四轮汽车；车框中心在图像宽度 50%、高度 60% 的位置；框宽占整图 30%、框高占整图 20%；`0.92` 表示模型认为这个判断有 92% 的可信度。

### 为什么必须使用三种模态

| 模态 | 提供的信息 | 典型优势 | 典型问题 |
|---|---|---|---|
| RGB | 颜色、纹理、外观细节 | 白天或光照正常时，便于区分类别 | 夜间、逆光、烟雾和低纹理场景会明显退化 |
| 热红外 | 目标与背景的温差 / 热辐射 | 弱光甚至无光时，人与有温度目标更显著 | 缺少颜色和纹理，温度接近时区分困难 |
| 深度 | 相机到物体的距离与几何结构 | 可辅助判断遮挡、前后关系和尺度 | 近距离无效区、远距离或噪声区域可能不可靠 |

官网希望模型学习“按场景取长补短”：例如夜间更依赖红外，遮挡或尺度变化时更多参考深度，光照正常时保留 RGB 的纹理识别能力。官方还特别要求：当某一个或多个模态的成像质量较差时，算法不能出现大幅性能波动。

### 覆盖的场景与难点

- **路口 / 交通监控**：人、双轮车、汽车、三轮车等目标可能远小、密集或被遮挡。
- **公园 / 安防巡检**：背景复杂，动物、座椅、垃圾箱、标识和灯等类别外观差异大。
- **室内场景**：灯、球、座椅等易与背景混淆，深度可提供结构线索。
- **空中场景**：无人机通常很小、天空背景纹理很少，定位精度尤其重要。
- **极端成像条件**：低照度、强逆光、烟雾、低纹理背景和遮挡，是本题要重点解决的退化因素。

### 官方允许的技术路线

- 算法类型不设硬性限制；可采用 CNN、Transformer 或其他机器学习方法。
- 推荐使用 Python 3.8+ 与 PyTorch，但不是强制要求。
- 鼓励做多源异构特征融合或检测架构改进；评审目标是提升复杂场景下的准确性与鲁棒性。
- 不限制本地或云端训练算力，但训练和推理必须离线完成，不能调用在线服务/API。

### 对团队的实际要求

1. 读取每组对应的 RGB、红外和 16-bit 深度图；不要把深度图当作普通 8-bit 灰度图随意读取。
2. 确保数据增强后三模态及目标框仍保持空间对齐；对几何变换必须同步应用于三张图和标签。
3. 训练一个输出 12 类边界框的检测模型，并在本地计算 `mAP@50-95`。
4. 推理时为每张测试图生成同名 TXT；没有目标也要生成空 TXT。
5. 通过 RGB-only、RGB+红外、RGB+深度、RGB+红外+深度的对照实验，证明融合设计的实际增益，并为半决赛技术报告保留证据。

> 参考：以上任务解释依据[官方赛题规则](https://www.aicomp.cn/tracks/tracks-1/3700.html)中的“赛题背景、应用场景、赛题任务、数据集说明、功能要求与约束条件”整理。

## 数据与输出格式

### 数据

- 训练集：2,000 组三模态图像，提供目标框标注。
- 初赛、复赛、半决赛：各 1,000 组不同测试数据。
- RGB：8-bit 三通道图像。
- 红外：三通道热辐射灰度堆叠图像。
- 深度：16-bit、单位毫米；0 或很小值代表无效深度。

### 标签与预测

训练标签：

```text
[class_id, norm_center_x, norm_center_y, norm_w, norm_h]
```

预测结果：

```text
[class_id, norm_center_x, norm_center_y, norm_w, norm_h, confidence]
```

要求：

- 每张测试图必须有一个同名 TXT；无目标时也要提交空 TXT。
- 每图最多 100 个预测框，超出部分按置信度截断。
- 非法类别、坐标或缺少置信度的预测无效。
- 将全部 TXT 打包为压缩包上传。

## 打分规则

- 排行榜指标：`mAP@50-95`。
- IoU 阈值：0.50、0.55、…、0.95，共 10 个阈值。
- 每类 AP 使用 101 点插值法，随后对类别和阈值取平均。
- 同类预测框按置信度从高到低匹配；同一个真值框只能匹配一次，重复框会记为 FP。
- 低于官方基线成绩的结果，赛事方有权认定为无效成绩。

奖项比例上限：复赛与总决赛的一、二、三等奖分别不超过有效作品数的 15%、25%、30%。

## 重要约束

- 只能使用官方训练数据；禁止用外部数据扩充训练。
- 可使用 ImageNet、COCO、Objects365 等公开预训练权重。
- 测试集不得用于训练、人工标注、篡改或泄露。
- 训练和推理必须离线完成，禁止调用在线服务或 API。
- 禁止对多个不同结构/训练阶段模型做简单投票或平均式集成。
- 作品必须原创，严禁抄袭、作弊或数据泄露。
