# v29：受限原图裁剪的小目标训练

更新：2026-09-29。用户明确选择保留YOLO26x、针对小目标改进训练，随后授权同步可迁移方案至D-FINE并分步提交GitHub。两个入口均已实施v29小目标裁剪，尚未启动正式训练；不承诺mAP50-95达到0.60。

## 目的与比较基线

v28原定目标是保留RGB预训练特征、引入局部质量辅助融合和P2细节、提前完成学习率衰减，提高困难场景泛化。最终是结构、日程、增强组合实验，不是单变量消融。它在固定100张验证集的最佳mAP50-95从YOLO v27的0.4096117765提高到0.4254824287，但sign/bicycle/light/uav下降，第39轮后明显过拟合；不能称全部小目标策略有效。程序检查通过也不等于精度目标通过。

v29保留v28网络和基础配方，唯一新增训练策略是受限小目标裁剪。假设：以一定比例从原始三模态图像裁取小目标周围区域，再缩放进网络，可以改善小目标特征与定位学习；完整画面继续占主导，避免模型只会识别局部。裁剪分支不叠加Mosaic和仿射裁切，是该策略的一部分，因此不能将其解释成“所有增强概率完全相同，只多一行crop”。本轮不换YOLO11m、不增加检测头/教师蒸馏/重复采样，也不修改预测算法。

## 数据依据

仅读取官方1900张train和100张val的图片尺寸与TXT。以下“小于32/64”指完整图长边缩放至1536后框面积平方根的像素值；不是COCO原图尺度的APs，也不是复赛真值统计。原TXT的重复框按原文计数，正式框架缓存仍可能移除重复行。

| person | 4795 | 1111 | 2569 | 754 | 327 |
| sign | 729 | 188 | 444 | 59 | 8 |
| bicycle | 576 | 180 | 363 | 90 | 23 |
| ball | 78 | 46 | 76 | 17 | 8 |
| light | 1777 | 130 | 556 | 58 | 2 |

训练集tricycle仅15个框，说明某些类别还受样本稀少限制，裁剪不等于增加独立样本。当前划分和官方标签保持不变，不通过重新挑选验证集抬高AP。

## 实现与参数

入口`train1.py`，运行名`AIC_RGBIRDepth_yolo26x_1536_v29_small_crop`；从`orgin_models/yolo26x.pt`官方基底重新迁移，`RESUME_PATH=None`。不继承v28 best或last，避免把继续训练与新增增强混成一个变量。网络架构标识仍为`reliability_v28`，它表示模型结构及推理协议；训练版本号是v29，两者不是同一概念。

YOLO保留1536、FP32/TF32关闭、batch1/nbs16、固定BN统计、AdamW骨干1e-5/颈头5e-5/辅助分支1e-4、100轮余弦、5轮预热、patience50、第41轮收尾及既有传感器扰动。保留每轮正式验证和按mAP50-95选择best，不设置首轮或阶段AP硬门槛。D-FINE适配见文末，不能把YOLO的100轮和融合模块当作两个入口共用配置。

共用配置`SmallObjectCrop`和窗口选择`choose_small_object_crop`已抽到`src/augmentation.py`，仅依赖NumPy与标准库。YOLO浮点数据集路径位于`src/yolo/aic/training.py`，D-FINE路径位于`src/dfine/training.py`，两者不相互导入训练器：

1. 只对25%的主训练样本尝试裁剪，不增加主索引数；Mosaic附加图不再触发该裁剪。
2. 从完整画面缩放后面积平方根小于64像素的目标中选择锚点；先在本图符合条件的类别中等概率选类，再选框，避免数量多的person完全主导。没有符合条件的框就回退。
3. 同时保留原宽、高的60%–80%，锚点完整包含在窗口中；其他相交框必须至少保留80%面积，否则拒绝整个窗口，而非丢弃其标注却保留目标碎片。最多尝试6次。
4. 先在原始五通道图上切出同一窗口，再用原连续浮点有效深度插值缩放。仅转换本次内存标签，不写回图像、TXT或数据划分。
5. 成功裁剪的分支只接现有传感器增强、等比填充、水平翻转和格式化；不叠加Mosaic、随机缩放平移或二次裁切。失败时执行原v28增强链。
6. 第41轮调用原收尾生命周期时关闭裁剪；有限加载器reset关闭旧worker，后续worker取得新状态。验证从第一轮起就不裁剪；预测仍用原完整画面协议。

以seed29在1900张训练图标签上每图尝试一次窗口提议：1301张含符合条件的目标，1079张取得合法窗口。它不是实际训练次数；若乘以25%的尝试率，仅可作约14.2%主样本成功裁剪的粗略参考。正式结果必须读取`small_crop_history.csv`的images/attempted/applied/fallback/applied_fraction。其计数来自训练实际消费的批次，不是worker预取量。

## 验收和运行

已运行`tests/test_v29_small_crop.py`和`tests/test_float_training_boundaries.py`，共15项CPU检查通过，覆盖原图框变换、原标注不变、五通道同步、严重截断窗口回退、独立裁剪增强链、批次组装、验证/收尾关闭和默认关闭不多消费随机数。首次测试中合成数据集桩缺少cache属性，补齐桩后通过；没有将测试失败伪称生产数据问题。

未进行GPU前向/反向、正式训练、全量预测、独立复评或显存探测。模型和尺寸与v28相同，但这不保证所有运行资源峰值相同。代码与文档在正式训练前保存独立Git基点，不自动启动长任务。

```powershell

```

查看前20轮时，优先看整体AP走势、sign/bicycle/ball/light/uav逐类结果，以及裁剪是否真正被消费；不以第一轮必须0.4决定去留。第41轮后裁剪计数应为零。最终与v28第39轮best在同一100张完整图上比较整体和逐类AP，避免只挑单类跨轮峰值。v29还没有效果结论。

`predict1.py`保留用户已选择的v28权重及输出路径，避免未训练就默认指向不存在的新权重。训练完成后显式选择v29实际目录：

断点恢复只填写本次v29同配方的last.pt；不能用v28断点替代，不能修改裁剪配方后绕过恢复签名。旧模型结构和历史预测兼容保留。

## D-FINE v29同步实施

v28给出的答案是：整体组合在本地验证集有1.5871个百分点改善，但无法分离结构、增强和日程各自的贡献，且未解决后期过拟合。不能把门控融合、P2细节或短日程单独标为已验证有效。v29裁剪只有数据处理正确性的检查，还没有精度结果。因此本次移植的是可对应实现的训练候选策略，不是宣称已获证实的D-FINE提分模块。

`train2.py`改为`AIC_RGBIRDepth_dfine_x_1536_v29_small_crop`，仍从本地官方`orgin_models/dfine_x_obj365.pth`迁移。无独立D-FINE v28训练，不虚构中间版本；两架构下一轮统一v29。

| 项目 | D-FINE处理 |
|---|---|
| 网络 | 保留D-FINE-X五通道首层；不照搬YOLO P3–P5门控、P2细节及双头损失 |
| 数据/输入 | 官方1900/100、1536、连续FP32，辅助模态有效深度插值与原预测协议保留 |
| 资源 | batch1、effective_batch16、val_batch1、workers2，不改变精度或自动探测显存 |
| 预训练保护 | 保留Objects365类别迁移，主学习率5e-5/骨干1e-5及原归一化设置 |
| 日程 | 保留60轮余弦、5轮预热、patience50；本来就是短日程，不扩为YOLO的100轮 |
| 新裁剪 | 与YOLO共用25%尝试率、原宽高60%–80%、64像素锚点阈值、80%可见性、6次尝试 |
| 收尾 | 第41轮同时关闭裁剪和原有随机缩小，传感器扰动及同步翻转保留 |
| 验证/预测 | 完整画面；原生D-FINE查询排序、FP32、max_det100，不使用YOLO NMS |

D-FINE在读取原始五通道后、传感器增强和LetterBox之前裁取；归一化xywh先转换为裁剪坐标，再转换为画布坐标。裁剪成功不叠加原scale_min随机缩小，失败执行原v27路径。训练标签只处理内存副本，磁盘原图/标签/划分不变。每轮样本数仍为1900，`small_crop_history.csv`从主进程实际消费的样本统计；诊断字段在送入官方模型及损失前移除。

共用模块纳入两框架训练源码快照及哈希；预测源码清单也记录该依赖，只有追溯清单变化，预测计算及根入口默认权重不变。YOLO本轮源码摘要有变，已启动的旧代码断点必须使用对应快照恢复，不放宽签名校验。实施时未发现活动python训练进程。
