## 结论与证据边界

v9用户反馈赛事53.4750，比v4的55.6000低2.1250分，确实未完成提分目标。v9后期存在过拟合；没有找到“预测未使用辅助模态”或“保存图片压缩了模型输入”的代码证据。没有在同一验证集重评两模型，因此不能排除其他运行差异，也不能把差距唯一归因于某一个参数。

此前一次叠加门控结构、更大输入、分组学习率、定制拼图与收尾策略，缺乏逐项收益证据。本轮不再以结构复杂度代替有效性，恢复有线上成绩支持的v4早期融合路线，保留后续已经查明的球类语义映射与审计能力。

## Git与权重核验

- `86411da:main.py`对应v4的运行名和lr0=1e-4；`86411da:三模态训练.py`是当时的五通道数据/训练实现。`a9ed7be`更早，main仍为v3较高学习率，不应冒充v4完整配方。
- v4 best.pt模型为原生DetectionModel，首层权重`[64,5,3,3]`；不是v9的独立门控融合器。实际一对多输出，12类顺序一致。
- v4首层IR/Depth切片L2范数约0.06538/0.04254，非零；RGB切片约9.94/8.01/8.06。证明不是永久冻结的零辅助权重，但仅凭范数不能量化模态贡献，也不能证明深度一定有益。
- v9首层RGB卷积`[64,3,3,3]`是设计如此，另有IR/Depth编码器。第63轮辅助梯度记录约3.81，门控均值约0.10–0.19；不支持“辅助通道根本没参与”，也不能证明增加了准确率。
- v4无明确的`sports ball → ball`同义类迁移；v10保留当前两头逐层迁移校验。这是合理补强，不是证明ball历史AP=0只有一个原因。
- v4旧训练集包含现验证集新增的样本，不能用v4训练好的best作为新初始化后，再把当前验证当成从未见过的数据。v10从官方COCO权重重新迁移。

## v10实施配方

1. 官方YOLO26l→五通道首层早期融合；移除本轮独立随机辅助分支，整个预训练主干共同接收模态信号。新增两个输入卷积切片仅初始化为0，之后正常训练；三模态图像始终真实输入，不是模态置零伪装。
2. 训练、验证、预测统一1920×1080内容，等比缩放后只补8像素成为1920×1088；不做1920方形训练，不把长边缩成1080。前40轮Mosaic=0.25（75%样本保持完整画面）、scale=0.3、translate=0.1、fliplr=0.5；复用已有矩形拼图及逐通道仿射组件，不宣称与v4原生随机Mosaic完全相同。第41轮关拼图，改为scale=0.1/translate=0.025的完整画面轻增强，避免v9后期几何正则化全部取消。仅RGB施加HSV=0.01/0.15/0.15，IR/Depth不做颜色增强；这不是已证明的单项提分幅度。
3. AdamW所有参数lr0=1e-4、wd=5e-4、batch=2/nbs=16、warmup=5、120轮余弦/lrf=0.01、cls_pw=0.25；保留v4主干更新强度，不再用2e-5，并缩短衰减周期。类别权重会同时影响该类正负项，收益仍待验证，不叠加稀有类重复采样。全尺寸显存未实测，用户可自行将batch改4，禁止自动探测或偷偷降分辨率。
4. 双头训练固定0.8/0.2，单头输出；v4的5000轮上限使前200轮双头权重仍以一对多为主，不能直接将epochs改200却沿用随epochs变化的原生双头衰减。v10日志损失取一对多头，与v4原生打印的头不同，不跨版本直接比较损失绝对值。
5. 从第一轮计早停，patience=30、min_delta=0。保留best(AP95)、best_map50候选、last与周期检查点。不为等待收尾强行继续训练，不在末尾额外重载复评。
6. FP32轮末验证与正式预测、单标签NMS、100框上限。预测默认新v10 best、1920/height1080，自动识别早期融合检查点并走共用固定矩形批量后端（batch=4），不再使用逐图v4原生补边。检查点存储结构版本和内容宽高，不匹配直接报错；prediction.json记录实际结构版本/尺寸/批次。历史v4仍可显式1280、yolo_profile=v4预测。用户的OUTPUT_PATH=`predict`保持不变，已有目录不覆盖。
7. 清洗数据1709/291和57文件修订原样保留，训练前核验既有审计，不重洗、不改变验证划分、不生成大NPY缓存。每轮仍留逐类/分域指标；辅助切片权重范数仅为参与学习的诊断，不当作贡献评分。

完整YOLO参数仍显式列于main.py，非检测任务参数不会因为写出来就参与训练。参数定义参照[Ultralytics官方训练说明](https://docs.ultralytics.com/modes/train/)，具体执行以本机8.4.152源码为准，没有升级依赖。

## 如何执行与判定

```powershell
uv run python main.py
# 训练完成后核对实际目录，重名运行会带后缀。
uv run python predict.py --weights runs/detect/AIC_RGBIRDepth_yolo26l_1920x1080_v10_early_fusion/weights/best.pt --imgsz 1920 --height 1080 --output predict_v10
```

这是待验证的基线修复候选，不是已证实“最优模型”。先与v9在同一1709/291划分的总体AP95、逐类及PNG/JPG分域表现对照，再看用户正式提交；不能要求v10必须复现旧验证集0.40370才算有效，也不能只按AP50峰值选权重。

目标60意味着相对v4还需4.4分，不能根据群聊推算“某技巧必加2分”。本轮按用户要求组合全尺寸、RGB增强和分阶段轻增强，不是单变量实验，最终涨跌不能直接归因到一个开关。如果仍无法突破，下一步优先结合正式训练保存的验证可视化，对船/灯/垃圾桶及少样本类进行约200张人工标注与三模态对齐复核，记录后再改标签；这项人工复核本轮未完成。进一步比较应固定划分并逐项改动。老师的难例挖掘须额外运行模型，本轮没有擅自启动；仅官方训练数据可用，拒绝多权重投票与测试集伪标注。
