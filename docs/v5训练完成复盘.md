读取对象为 runs/detect/AIC_RGBIRDepth_yolo26l_1280_v5_full 的 args.yaml、四张 Box 曲线、两张混淆矩阵、labels.jpg、optimization_recipe.json、per_class_metrics.csv、results.csv、results.png、train.log。没有执行新训练、模型加载、推理、测试或统一复评。

## 总体结论

### 初始化与过拟合的澄清（2026-09-18）

v5 的 args.yaml 明确记录 `model: ./orgin_models/yolo26l.pt`、`pretrained: true`、`resume: false`，本次从官方 COCO 预训练权重重新迁移，没有接着 v4 的比赛权重训练。orgin_models 中的官方权重并非“完全没训练过”，而是没有训练过本项目的比赛数据；换回同一权重重跑相同配方不会自动消除过拟合。

训练分类损失下降本身是正常的优化结果，不是验证 mAP 下跌的直接原因；训练损失下降同时验证损失上升、验证 AP 退化，才是本次后期过拟合的证据。有限且存在相似帧的训练集，即使重新从官方预训练开始，也可能在反复学习后过拟合。不能仅凭曲线证明所有具体机制或某个增强单项导致了退化。

ball、seat、bicycle 的改善支持组合配方对部分弱类有收益，但多个设置同时变化，且验证口径改变，不能证明每一项都有效，也不能证明所有弱类或线上总分都改善。完全随机初始化不是本次方案，不建议为了避免“之前训练过”而丢弃预训练迁移能力。

后期过拟合明显，但保存的 best.pt 来自第 34 轮，不是过拟合更重的末轮。当前没有 v5 线上成绩，不能声称已提高比赛得分或达到 60 分。v5 改善了球类，但总体峰值没有明显突破。

| 运行 | 最高 mAP50 / 轮次 | 最高 mAP50-95 / 轮次 |
|---|---|---|
| 旧运行 | 0.57753 / 83 | 0.37746 / 79 |
| v3 | 0.55881 / 73 | 0.37290 / 150 |
| v4 清洗版 | 0.60632 / 42 | 0.40370 / 100 |

相对 v4，v5 峰值 AP50 下降 0.797 个百分点，AP50-95 增加 0.255 个百分点。v5 验证采用单标签 NMS、pad=0，v4 为另一种候选/填充口径，因此不能当作严格相同流程的消融比较；本次不增加统一复评。

第 34 → 234 轮：train/box 1.20448 → 0.85485，train/cls 0.59951 → 0.28977；val/box 1.40639 → 1.54091，val/cls 1.39871 → 1.53543；mAP50-95 0.40625 → 0.37899。训练拟合继续增强，验证泛化退化，支持后期过拟合，而不是只看到训练 loss 低就认定。

第 161 轮收尾将训练 loss 明显降低，部分源于增强变轻，不能全部解读成学习进步。第 160/161 轮 mAP50-95 为 0.38980/0.39001，之后没有超越 34 轮最佳。8.819 小时训练，234 轮停止，patience=200；该过长耐心值与过晚收尾没有得到本次结果支持。此前建议这两项是为了留出收尾机会，结果未达预期，应撤回它们“有望解决泛化”的强期待。

## 图片与配置解读

PR 曲线与最终日志一致，ball≈0.423，而非此前的零；sign、bicycle、light 仍是弱项。混淆矩阵 ball 6 个匹配、6 个漏检，38 个未匹配球候选；这与最佳 F1 点 ball recall≈0.333 不同，因为阈值和统计口径不同。当前显式 conf=0.001，混淆矩阵筛选阈值也随之降低，background 列的大量未匹配候选不能直接当作正常展示阈值下的误检数，更不能视为数据集应删除的样本数。

F1 曲线最高宏平均约 0.61、conf≈0.349；P 曲线接近 1 时 R 已接近零，不能据此宣称模型很好。R 曲线低阈值宏平均约 0.67，说明提高阈值会损失召回；F1 最佳阈值不是 AP 提交最佳阈值。本轮不修改用户 conf/iou。

labels.jpg 与 JSON 一致：person 4028、animal 2397、ball 83、tricycle 25 等，明显长尾且大量小框；图本身不能证明所有标注都正确。JSON 确认每轮 2124 主样本，较原 1744 增加约 21.8%；因此相同轮数不是相同训练量。args 确认 1280、AdamW 1e-4、BF16、4 workers、5000 上限、200 耐心值；CSV 六组学习率显示骨干为其他层 0.2 倍，配方确实执行。5000 上限仍影响双头损失，不能视为纯早停预算。

## 接下来怎么做

不继续拉长训练、不续训最后权重，也不因为本地小幅增长立即重跑整套。保留 v4 55.6000 线上基线；用户可先提交 v5 best.pt（34 轮），另一个单模型候选是 best_map50.pt（41 轮）。逐类 CSV 显示 41 轮 ball≈0.403、garbage can≈0.627，与 34 轮权衡不同；不能集成，也不能保证 AP50 权重线上更好。

若以后授权重新训练，合理候选是把实际收敛周期缩短到约 60–100 轮、patience 30–50、在 30–50 轮左右进入收尾，保留球类迁移与温和分层微调。不能简单把 epochs 改小而忽略双头损失日程；也不能仅依据长训退化证明网络容量一定过大。更换架构或真实场景验证划分是独立路线，而非一次叠加更多增强。这里仅为候选，不修改 main.py 参数、不启动实验。

## 代码清理与 token 约束

评估模型.py 是可选统一复评工具，不是无价值，但训练/预测均不导入它。tests 只在人工执行 pytest 或冒烟脚本时运行，不会因文件存在而消耗模型计算；runs/config_checks 为过去的资源/冒烟检查产物，不被当前训练引用。按本次要求，从原位置移入 runs/code_cleanup/ 的带时间戳备份，同时移走 .pytest_cache；可以恢复。保留 main.py、predict.py、训练优化.py、三模态训练.py、准备三模态数据集.py，以及所有正式训练权重、日志、数据与清洗审计。

仓库 AGENTS.md 原有“提交前运行 pytest”，CLAUDE.md、README.md 也列出测试命令；本轮撤销自动测试要求。只读检查到用户全局 Codex AGENTS.md 当前为空，没有从该文件发现强制测试规则。技能指令来自会话提供的已有技能目录，其中 TDD/执行计划确有测试要求；不能把它们说成这次训练代码自动触发的测试，也没有证据证明其由之前的代理新建。本轮不改用户全局技能或设置，只落实本项目不自动测试的明确约束。

读取大量源码、技能文档、图片与工具输出都会增加 token；不是 GPU 运行多久就对应多少 token。本轮仅使用已有产物，并记录检查范围。后续不自动运行测试、额外复评或为其生成脚本。
