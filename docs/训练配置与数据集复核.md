# 训练配置与数据集复核

复核日期：2026-09-15。阅读范围为 `docs/` 中的七份资料，未读取 `比赛资料/`；以本机文件和已安装的 Ultralytics 8.4.152 实现复核文档中的结论。

## 1. 结论与适用范围

最新训练时长设置为 `epochs=1000`、`patience=100`：最多训练 1000 轮，验证指标连续 100 轮没有刷新最佳值时自动停止。学习率按 1000 轮规划，`close_mosaic=40` 在计划中的最后 40 轮生效；若模型提前停止，可能不会进入关闭 Mosaic 阶段。官方 2000 张图全部保留，其中 1744 张用于训练，256 张作为独立验证集。

当前 `datasets/` 在文件来源、配对和可加载性上有效，1744/256 的数量比例也合理，但验证集的分布代表性不足，不能据此承诺一次训练达到最优成绩。官方原始图像、标注和测试集均未修改。

2026-09-15 已切换为三模态早期融合训练：`main.py` 使用 `datasets/multimodal_new_labels/data.yaml`，输入为 RGB（3）+ 红外（1）+ 深度（1）共 5 通道。该目录位于 `datasets/` 内；原有 `datasets/train`、`datasets/val` 保持旧标注副本不变。新版标签来自 `new_labels_2000`，并保留既有 1744/256 划分。

全量核验确认同名三模态尺寸一致：1851 组 PNG 均为 1920×1080，149 组 JPG 均为 640×360。此前上采样说明源于样本索引错配后的错误判断，已纠正。加载器检查同名与同尺寸，再将 RGB、红外、深度组合为五通道；几何增强同步执行，HSV 关闭。

本次代码复核修正了可见光通道顺序：框架仅对三通道图自动执行 BGR→RGB，五通道图必须在融合前自行转换。缓存随融合实现或源图更新而失效。续训通过 `main.py` 的 `RESUME_PATH` 指定五通道检查点，继续使用自定义训练器；不要使用普通 YOLO CLI 续训。训练与验证各自复制增强参数，缩小训练样本比例时仍使用完整验证集。

额外发现：`000032_029_00000001` 与 `shuming_486_00000001` 是完全相同的图像，均在训练侧，两套标签的框坐标略有不同。它不造成跨集泄漏，但属于训练数据中的重复监督。

跨集相似图筛查采用 PIL 灰度缩放至 96×96、去均值后归一化相关，并复核同类框距离。256×1744 配对中最高相关度为 0.8864，超过 0.85 的 7 对均未同时满足双向框距离中位数小于 0.03。**本次筛查未发现明确近重复泄漏，但不能证明所有场景完全独立**。与旧文档的 11 对/0.8948 不完全一致，是缩放和距离计算实现口径不同；文件名前缀也不能代表所有真实场景。

### 验证集的主要不足

| 类别 | 训练框数 | 验证框数 | 验证中含该类的图数 |
|---|---:|---:|---:|
| person | 3985 | 1514 | 133 |
| boat | 128 | 7 | 2 |
| animal | 2438 | 623 | 149 |
| seat | 540 | 81 | 27 |
| sign | 731 | 78 | 41 |
| bicycle | 570 | 96 | 27 |
| car | 1506 | 65 | 18 |
| ball | 77 | 12 | 11 |
| light | 1397 | 58 | 35 |
| garbage can | 252 | 30 | 28 |
| uav | 201 | 3 | 3 |
| tricycle | 23 | 2 | 2 |

1. **低分辨率样本缺席验证集**：149 张 640×360 JPG 全在训练侧，验证侧全部为 1920×1080 PNG；官方初赛测试集包含 155 张 JPG。当前验证指标无法直接评价这类输入。
2. **无人机验证尤其薄弱**：全数据 204 个旧版无人机框，其中 191 个在 JPG 中；验证集只有 PNG 中的 3 个无人机框。
3. **稀有类 AP 波动大**：船只来自 2 张验证图，三轮车也仅来自 2 张。总 mAP 对各类等权平均，增加训练轮数不能增加独立验证样本量。
4. **场景密度偏移**：验证图平均约 10.0 个框，训练图约 6.8 个；验证侧行人/动物更集中。

正式定稿数据时，建议按内容核实的场景组重新做分层留出：保留约 15%–20% 验证图，同时覆盖低分辨率 JPG、主要场景和稀有类别。比例和类别框数只能是目标，不能为凑数拆开相邻帧/同场景。应在看模型成绩之前固定划分，避免反复按验证分数调整样本。此次未移动现有样本。

### 官方新版标注

`new_labels_2000/` 与原始 `labels/` 有 382 个文件不同。新标注共 15195 行，比旧版多 778 行；主要为 car 增加 378 框、light 增加 380 框。

新版结构校验通过，但仍有 5 行坐标略越界、1 处重复行，另有 1 个空标注 `shuming_102_00000228.txt`。空标注在框架中合法，但不能仅凭空文件确认图像确为纯背景。训练已使用新版的独立副本；标签不会直接写入旧目录的硬链接文件，避免连带改动原始标注。

## 3. 本机与配置选择

本机检测到 RTX 5080 16 GB、Ryzen 9 9950X（16 核/32 线程）、约 31.2 GiB 内存。当前环境为 PyTorch 2.14.0+cu132、Ultralytics 8.4.152；CUDA 矩阵计算和 BF16 支持检查通过。检查时可用系统内存约 16.4 GiB，D 盘空闲约 77.7 GiB。

| 参数 | 本次值 | 依据 |
|---|---|---|
| model | 本地 yolo26l.pt | 在优先保留 1280 输入的前提下，l 的容量和本机实测显存可兼顾；未做跨模型精度竞赛，不能宣称 l 是本数据的已验证最优 |
| imgsz | 1280 | 960 下框短边不足 16 像素的比例为 19.93%，1280 下为 10.97%；框像素统计基于原始标注、保持比例缩放，未计增强 |
| batch | 4 | 合成密集批次和真实数据训练通过；保留桌面显存余量，不沿用未经测量的 batch=32 |
| amp | bf16 | RTX 5080 原生支持；合成批次损失、梯度均有限，真实训练正常 |
| workers | 4 | 实测 Windows 多进程数据加载正常，兼顾 9950X 供数能力与子进程内存 |
| cache | disk | 利用 NVMe，缓存融合后的五通道图像以减少每轮三文件解码；缓存生成在 `datasets/multimodal_new_labels` 内 |
| optimizer | MuSGD | 显式固定当前版本的长周期 auto 配方，lr0=0.01、momentum=0.9、warmup_bias_lr=0 |
| warmup_epochs | 5 | 为预训练模型到 12 类检测头的适配留出预热阶段 |
| nbs | 64 | 预热后每约 16 个 batch 累积更新一次；这不等同于 BatchNorm 也看到 64 张图 |
| epochs | 1000 | 为后续增加官方允许的训练数据预留训练上限；实际训练轮数同时受早停控制 |
| patience | 100 | 验证 fitness 连续 100 轮没有提高时自动停止；最终仍使用整个训练过程中保存的 `best.pt` |
| cos_lr / lrf | True / 0.01 | 按最多 1000 轮规划余弦下降；若提前停止，学习率不会走到计划末值 |
| close_mosaic | 40 | 计划在第 960 轮后关闭 Mosaic；提前停止时可能不会进入这一阶段 |
| scale | 0.3 | 缩放范围约 0.7–1.3，减少过强缩小对小目标的损害 |
| cls_pw | 0.25 | 对类别不均衡做温和逆频率加权；训练集归一化权重约 0.54–1.95，避免完整逆频率的极端权重 |
| val / conf / iou | True / 0.001 / 0.7 | 以验证 PR 曲线选权重；0.7 是 NMS 阈值，不是评测 IoU 阈值 |
| max_det | 100 | 与赛题每图最多 100 个预测框一致；当前标注最大为 66 个 |
| save_period | 25 | 除 best/last 外定期保留中间权重，便于排查或恢复 |

模型选择原则：n/s 适合速度优先，m 适合更低的显存和计算预算，l 在本机兼顾较高输入分辨率与预训练容量；x 的计算开销明显更高，其 COCO 优势不保证迁移到本赛题。官方公布的 l/m 参数和 FLOPs 是融合后的部署统计，训练网络保留双检测分支，因此实际训练时显示的参数量更高。[官方模型比较](https://docs.ultralytics.com/models/yolo26/)

当前以 1000 轮作为上限，并用 100 轮耐心值控制早停。增加上限不会强制训练满 1000 轮，但会改变余弦学习率和 `close_mosaic` 的时间位置；模型选择始终以 `best.pt` 为准。[训练参数说明](https://docs.ultralytics.com/modes/train/)

五通道短训只验证了 1280、batch=4 能稳定运行，不能准确换算 1000 轮总耗时。正式耗时应以第一个完整 epoch（包含训练和 256 张验证图）的实测时间估算；早停可能明显缩短总时长。

`main.py` 还在导入 Ultralytics 前启用离线模式、关闭自动安装，并检查本地权重与 CUDA/BF16 可用性。预训练权重来自 `orgin_models`，不加入外部训练样本。

## 4. 对既有经验文档的校正

- `auto_augment="randaugment"` 是分类任务增强，不会自动增强当前 detect 任务。
- 本版本 `optimizer="auto"` 根据估算迭代次数在 AdamW/MuSGD 之间选择，并不是始终 MuSGD。
- 本版本检测 fitness 权重为 `[0, 0, 0, 1]`，即使用 mAP50-95；旧经验中“best.pt 不一定按最高 mAP50-95 选”的概括不适用于本次安装版本的正常检测训练。
- JPG 深度图实际上是 8-bit RGB，只有 1851 张 PNG 深度图是 16-bit。以后做融合不能将全部深度文件按毫米数值统一处理。
- “框架能够加载”仅说明格式可接受，不能证明场景独立、标注正确或验证集具有代表性。

## 5. 验证与使用

### 本次五通道实测（优先于下方历史 RGB 记录）

使用正式 1280 分辨率、batch=4、BF16、MuSGD、磁盘缓存和绘图配置完成 9 张训练图的 1 轮短训及完整 256 张验证图验证，保存并重新加载 best.pt 成功。显存峰值已分配 10.89 GiB、保留 11.87 GiB。配置 workers=4，框架因短训仅 3 个批次自动使用 3 个加载进程；正式完整数据集的 4 进程五通道长跑仍需观察。

正式配置为 YOLO26l、1280、batch=4、最多 1000 轮、早停耐心值 100、5 轮预热、计划末 40 轮关闭 Mosaic、余弦学习率和温和类别加权。完整五通道磁盘缓存约 18 GiB；当前约 16 GiB 可用内存不适合全量 RAM 缓存。完整训练没有启动。日志位于 `outputs/training_check_latest.log`，烟雾模型仅用于检查流程。多通道框架能力参考 [Ultralytics 官方说明](https://docs.ultralytics.com/datasets/detect/coco8-multispectral/)，项目实际行为以安装版本代码及上述实测为准。

已完成所有官方训练 RGB 图像解码和 SHA-256 检查、全部标签结构与来源检查、三模态文件头核对、跨集相似图筛查，以及本机合成批次的训练显存探测。

此前的 RGB 小样本检查仅可说明旧单模态配置可运行。切换后三模态加载器已用真实新版标签完成 1 个 epoch、2 个训练批次的 GPU 烟雾训练：模型首层确认为 5 通道，数据加载、五通道前向/反向、权重迁移和保存均正常。该烟雾训练不代表正式精度或正式显存峰值。

另外用 16 张高密度 PNG（每图 36–50 个原始框）与 16 张 JPG 混合重复烟雾训练，覆盖不同原图分辨率和密集增强场景，8 批均正常，峰值已分配 10.96 GiB、已保留 11.81 GiB。小样本检查用于验证运行能力，不能用其中的 mAP 推断正式训练精度。

旧标注副本曾通过框架完整加载 1744/256 张图像。新版三模态副本沿用同一图像划分，训练前会由框架重新生成标签缓存；`main.py` 正式入口是 `fraction=1.0`、`epochs=1000` 和 `patience=100`，未遗留烟雾测试的小样本设置。

检查产物保存在 `runs/config_checks/`，仅用于验证流程，不是正式模型。可复核的本地辅助脚本位于已忽略的 `outputs/reports/`，不会混入参赛模型或原始数据。

正式运行：

```powershell
uv run python main.py
```

正式输出目录为 `runs/detect/AIC_RGBIRDepth_yolo26l_1280/`，重名时框架自动递增；最终使用其中的 `weights/best.pt`。意外中断时从实际目录的 `weights/last.pt` 恢复。完整训练没有在本次配置检查中启动。

模型预测可视化图片不等于提交文件。赛题要求每张测试图一个同名 TXT，列顺序为 `class_id cx cy w h confidence`，最多 100 个框，未检出也要写空文件；当前 main.py 顶部的示例只负责预测与保存图片，尚未实现完整提交打包。
