未匹配名称意味着相应类别输出参数未按语义迁移，不意味着整个分类分支或骨干从零训练。仅做球类明确对应，不把包含路灯/室内灯的 light 强行等同于 traffic light，也不把包含多种座椅的 seat 强行等同于 chair。迁移属于合理初始化实验，尚无证据证明它是 ball AP=0 的主要原因。

验证：`uv run pytest tests/ -q` 共 18 项通过，涵盖修改训练上限时的 Mosaic 时间、球类双分支输出参数迁移、原模型名称不变、五通道权重完整恢复及既有加载器测试。CPU 构造模型与测试通过不代表完整训练精度已经提高。

完整数据检查及新版类别统计见 [数据集成分与划分记录](数据集成分与划分记录.md)。已核实 2000 个标签与官方新版逐字节相同；ball 验证框逐个检查未见明显错配。不能把该结论扩展为所有类别都无错标。

实验顺序：

1. 运行 v3，与同划分 v2 的 0.37746 和分类别 AP 比较；记录关闭 Mosaic 前后趋势。训练入口为 `uv run python main.py`。本次只修改配置并做测试，未自动启动正式训练。
2. 如有收益，分别消融“仅修日程”与“仅球类别名”，确认收益来源；如无收益，保留 v2 为基线，不凭预期替换最佳模型。
3. 用同一场景划分做 RGB 对照诊断，检验五通道早期融合是否带来实际增益；RGB 对照用于研究，最终方案按比赛要求融合三模态。若无增益，再检查配准/深度尺度，并比较单模型内部的分支特征融合。
4. 稀有类采样与目标裁剪各作为独立实验，只使用 train，三模态同步。暂不依据单次 AP 加大 cls_pw 或启用过采样，避免重复强化少数场景。
5. 训练方案固定后，再比较其他模型；若用官方全部 2000 张训练最终提交模型，应先从独立验证实验确定训练日程，不能将训练集 AP 当独立验证分数。官方测试仅用于合规推理提交，不加入训练。

## 1. 结论与适用范围

v1 训练时长设置为 `epochs=1000`、`patience=100`：最多训练 1000 轮，验证指标连续 100 轮没有刷新最佳值时自动停止。旧学习率按 1000 轮规划，`close_mosaic=40` 在计划中的最后 40 轮生效；提前停止可能错过关闭 Mosaic 阶段。官方 2000 张图全部保留，其中 1744 张用于训练，256 张作为独立验证集。

当前 `datasets/` 在文件来源、配对和可加载性上有效，1744/256 的数量比例也合理，但验证集的分布代表性不足，不能据此承诺一次训练达到最优成绩。官方原始图像、标注和测试集均未修改。

2026-09-16 已收敛为单一数据集结构：`main.py` 使用 `datasets/data.yaml`，`datasets/` 下仅有 `train/`、`val/` 两个数据目录。输入为 RGB（3）+ 红外（1）+ 深度（1）共 5 通道；标签来自官方 `new_labels_2000`，并保留既有 1744/256 划分。官方旧标注仍保存在原始数据目录。

全量核验确认同名三模态尺寸一致：1851 组 PNG 均为 1920×1080，149 组 JPG 均为 640×360。此前上采样说明源于样本索引错配后的错误判断，已纠正。加载器检查同名与同尺寸，再将 RGB、红外、深度组合为五通道；几何增强同步执行，HSV 关闭。

本次代码复核修正了可见光通道顺序：框架仅对三通道图自动执行 BGR→RGB，五通道图必须在融合前自行转换。缓存随融合实现或源图更新而失效。续训通过 `main.py` 的 `RESUME_PATH` 指定五通道检查点，继续使用自定义训练器；不要使用普通 YOLO CLI 续训。训练与验证各自复制增强参数，缩小训练样本比例时仍使用完整验证集。

正式定稿数据时，建议按内容核实的场景组重新做分层留出：保留约 15%–20% 验证图，同时覆盖低分辨率 JPG、主要场景和稀有类别。比例和类别框数只能是目标，不能为凑数拆开相邻帧/同场景。应在看模型成绩之前固定划分，避免反复按验证分数调整样本。此次未移动现有样本。

本机检测到 RTX 5080 16 GB、Ryzen 9 9950X（16 核/32 线程）、约 31.2 GiB 内存。当前环境为 PyTorch 2.14.0+cu132、Ultralytics 8.4.152；CUDA 矩阵计算和 BF16 支持检查通过。检查时可用系统内存约 16.4 GiB，D 盘空闲约 77.7 GiB。

| batch | 4 | 合成密集批次和真实数据训练通过；保留桌面显存余量，不沿用未经测量的 batch=32 |
| amp | bf16 | RTX 5080 原生支持；合成批次损失、梯度均有限，真实训练正常 |
| workers | 4 | 实测 Windows 多进程数据加载正常，兼顾 9950X 供数能力与子进程内存 |
| cache | disk | 利用 NVMe，缓存融合后的五通道图像以减少每轮三文件解码；缓存生成在 `datasets/train` 和 `datasets/val` 内 |
| optimizer | MuSGD | 显式固定当前版本的长周期 auto 配方，lr0=0.01、momentum=0.9、warmup_bias_lr=0 |
| warmup_epochs | 5 | 为预训练模型到 12 类检测头的适配留出预热阶段 |
| nbs | 64 | 预热后每约 16 个 batch 累积更新一次；这不等同于 BatchNorm 也看到 64 张图 |
| epochs | 1000 | 为后续增加官方允许的训练数据预留训练上限；实际训练轮数同时受早停控制 |
| patience | 100 | 验证 fitness 连续 100 轮没有提高时自动停止；最终仍使用整个训练过程中保存的 `best.pt` |
| cos_lr / lrf | True / 0.01 | 按最多 1000 轮规划余弦下降；若提前停止，学习率不会走到计划末值 |
| close_mosaic | 40 | 计划在第 960 轮后关闭 Mosaic；提前停止时可能不会进入这一阶段 |
| scale | 0.3 | 缩放范围约 0.7–1.3，减少过强缩小对小目标的损害 |
| cls_pw | 0.25 | 对类别不均衡做温和逆频率加权；训练集归一化权重约 0.54–1.95，避免完整逆频率的极端权重 |
| val / conf / iou | True / 0.001 / 0.7 | 以验证 PR 曲线选权重；0.7 是 NMS 阈值，不是评测 IoU 阈值 |
| max_det | 100 | 与赛题每图最多 100 个预测框一致；当前标注最大为 66 个 |
| save_period | 25 | 除 best/last 外定期保留中间权重，便于排查或恢复 |

模型选择原则：n/s 适合速度优先，m 适合更低的显存和计算预算，l 在本机兼顾较高输入分辨率与预训练容量；x 的计算开销明显更高，其 COCO 优势不保证迁移到本赛题。官方公布的 l/m 参数和 FLOPs 是融合后的部署统计，训练网络保留双检测分支，因此实际训练时显示的参数量更高。[官方模型比较](https://docs.ultralytics.com/models/yolo26/)

历史 v1 以 1000 轮作为上限，并用 100 轮耐心值控制早停。增加上限不会强制训练满 1000 轮，但会改变默认余弦学习率和 `close_mosaic` 的时间位置；当前 v3 已独立处理两个日程，模型选择仍以 `best.pt` 为准。[训练参数说明](https://docs.ultralytics.com/modes/train/)

五通道短训只验证了 1280、batch=4 能稳定运行，不能准确换算 1000 轮总耗时。正式耗时应以第一个完整 epoch（包含训练和 256 张验证图）的实测时间估算；早停可能明显缩短总时长。

`main.py` 还在导入 Ultralytics 前启用离线模式、关闭自动安装，并检查本地权重与 CUDA/BF16 可用性。预训练权重来自 `orgin_models`，不加入外部训练样本。

## 4. 对既有经验文档的校正

- `auto_augment="randaugment"` 是分类任务增强，不会自动增强当前 detect 任务。
- 本版本 `optimizer="auto"` 根据估算迭代次数在 AdamW/MuSGD 之间选择，并不是始终 MuSGD。
- 本版本检测 fitness 权重为 `[0, 0, 0, 1]`，即使用 mAP50-95；旧经验中“best.pt 不一定按最高 mAP50-95 选”的概括不适用于本次安装版本的正常检测训练。
- JPG 深度图实际上是 8-bit RGB，只有 1851 张 PNG 深度图是 16-bit。以后做融合不能将全部深度文件按毫米数值统一处理。
- “框架能够加载”仅说明格式可接受，不能证明场景独立、标注正确或验证集具有代表性。
