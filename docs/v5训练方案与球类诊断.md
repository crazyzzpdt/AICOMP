## 线上证据与决策

用户反馈 v4 得分 55.6000，v4 epoch50.pt 得分 53.2540，后者低 2.3460 分。这两次提交的完整参数与 ZIP 指纹未提供，因此不能据此反推评分公式；但已有结果不支持仅凭本地 mAP50 更高就替换正式基线。保留 v4 及其全部产物作为线上基线。v5 的 best.pt 继续按官方文档的 mAP50-95 选取，同时独立保存另一个指标的峰值。

本轮按用户授权实现一套组合优化配方，用户自行启动正式训练；不是单变量消融，后续若改善也不能据此断定每个组件都有独立收益。

## ball 检查结论与边界

- 本轮逐文件读取现有标签，train 有 67 张含球图、83 个球框；val 有 11 张含球图、12 个球框，ball ID=7。没有出现球类缺失或被 classes/single_cls 参数过滤。
- 五通道加载顺序为 RGB、红外、深度。安装版本 Format 只对三通道图反转颜色，五通道保持顺序，与 predict.py 一致。
- v4 日志明确记录 sports ball → ball，并迁移 5/12 类。源码只把检测头分类输出层中对应行迁移，两个分支都在范围内。本轮未执行模型构建来检验实际参数；v5 将在用户正常开训时逐项核对两个分支的球类权重与偏置，发现迁移不一致直接报告具体参数，避免静默从随机初始化训练 ball。
- 框架 cls_pw 将该类别全部 BCE 项一起乘权重，包含正、负项。v4 的 ball 权重约 1.436，不能解释为只增强球类正样本。v5 关闭该加权，改用受限采样增加含弱类图的出现频率。这里是配方限制，并非已证实的框架错误。
- 历史 v3 诊断曾记录早期权重能覆盖部分验证球，长训后的 best.pt 退化；这支持迁移能力遗忘或跨场景泛化不足。该历史诊断不是本轮新运行，也不能直接代表 v4 的早期球类 AP。
- 既有尺度记录中，val 12 个球有 8 个在 1280 输入下短边不足 16 像素；其余较大篮球也漏检，单纯加分辨率不能解释全部问题。训练文件中存在连续编号的含球序列，重复帧数量不等于独立场景多样性。

结论：尚无证据证明 ball 因代码错误完全没有学习；现有证据更支持稀少场景、小目标与微调泛化问题。静态检查不能排除所有运行时问题，也不能证明 v5 已解决 AP=0。

## 已实现配方

唯一训练入口仍是 main.py，新增训练优化.py 作为辅助模块；模型保持标准五通道 YOLO26l，兼容现有 predict.py。

| 项目 | v5 设置与目的 |
|---|---|
| 初始化 | 本地 orgin_models/yolo26l.pt，从 COCO 重新迁移，RESUME_PATH=None；不从退化的球类输出继续长训 |
| 数据 | datasets/data.yaml，原有清洗版 1744/256 划分，官方原图与标签文件不再改动 |
| 采样 | 针对 seat/sign/bicycle/ball/light/garbage can 使用频率平方根重复因子；每轮原图全覆盖，每图主采样最多 3 次，文件名场景组最多增加 8 项 |
| 场景限制 | 前缀组和间隔大于 50 的纯数字连续段，仅用于限制附加采样；不宣称已解决所有视觉同场景识别。Mosaic 内部额外选图不计入主采样上限 |
| 目标裁剪 | 含弱类图 35% 概率从原尺寸图裁剪，优先球；保留至少 55% 宽高、完整选定目标及画面内其他类别的可见框，五通道同步；161 轮起关闭 |
| RGB 增强 | 仅前三通道 HSV，幅度 0.015/0.25/0.20；不改变红外/深度的颜色与距离编码 |
| 模态随机缺失 | 10% 概率置零一个辅助通道，RGB 总保留，仅训练前 160 轮启用 |
| 优化器 | AdamW，首层/颈部/检测头 lr0=0.0001，骨干层 lr0=0.00002；沿用 200 轮余弦衰减 |
| 类别权重 | cls_pw=0，使用采样改善曝光，避免叠加扩大弱类所有负样本 BCE |
| 空间增强 | mosaic=0.25，前 160 轮开启，第 161 轮关闭；scale=0.2、translate=0.05，fliplr=0.5 |
| 资源 | imgsz=1280、batch=4、nbs=16、BF16、workers=4、prefetch=1、不锁页、disk 缓存 |
| 时长 | 上限 5000、patience=200；默认双头损失日程保持原配方，不启用 loss300 候选，以保留当前 NMS 分支学习比例 |
| 验证 | NMS 一对多头，单标签候选筛选、pad=0，与当前逐张预测接近；匹配及 AP 计算仍使用框架标准实现 |
| 留存 | best.pt/last.pt；独立 best_map50.pt/best_map5095.pt；每 50 轮周期检查点 |
| 记录 | optimization_recipe.json：真实类频次、标签指纹、采样轮长及额外参数；per_class_metrics.csv：每轮 12 类 P/R/AP；运行目录保存三份训练源代码快照 |

新验证设置意味着 v5 本地曲线与 v4 多标签、额外填充的曲线存在口径差异。重采样使每轮主样本增加，一轮不再等于 1744 次取样，不能只按轮数比较训练量；日志与配方文件记录实际轮长。权重保存只是分别择优，最终提交仍使用单个模型。

当前默认运行目录为 runs/detect/AIC_RGBIRDepth_yolo26l_1280_v5_full。执行：

```powershell
uv run python main.py
```

训练完成后使用实际运行目录（重名会递增）中的 best.pt 生成独立输出：

```powershell
uv run python predict.py --weights runs/detect/AIC_RGBIRDepth_yolo26l_1280_v5_full/weights/best.pt --output predict_v5
```

predict.py 中用户自行修改的默认权重路径和阈值本轮不改。新配方标记为 v5_full_nativecrop_polish，只能恢复同标记的中断检查点；旧 v5_weakclass 和 v4 不可作为原状态续训。

可选生成单模型多标签候选包，必须使用另一个输出目录；不是要求本轮自动执行，也不保证高于上面的基准包：

```powershell
uv run python predict.py --weights runs/detect/AIC_RGBIRDepth_yolo26l_1280_v5_full/weights/best.pt --multi-label --output predict_v5_multilabel
```

先保留相同权重、尺寸与 conf/iou，仅比较候选筛选差异；不要把多标签、更高尺寸、不同权重同时改变后宣称某一项有效。若愿意做正式训练后的独立验证，可先在 val 比较，再决定提交方式；本轮按用户要求不运行。参考 [官方 NMS 参数](https://docs.ultralytics.com/reference/utils/nms/) 与 [数据增强说明](https://docs.ultralytics.com/guides/yolo-data-augmentation/)，项目阶段关闭和原尺寸裁剪为自定义实现，不是官方效果保证。

## 为何本轮没有直接替换框架

用户允许采用先进框架；当前优先引入适合长尾检测的采样思想和预训练分层微调，而保留线上已达到 55.6000 的模型结构。更换为 D-FINE/Objects365 需要另外适配五通道、检测头、环境和预测；不能保证比这些定向修正更有效，也不能视为改权重路径即可完成。

后续若 ball 仍长期为零，per_class_metrics.csv 可以定位何时退化，再据训练/验证原图诊断漏检、错分类或定位不足；不从测试图补标，不上传赛事数据，不加入外部训练样本。

方法参考：[Detectron2 RepeatFactorTrainingSampler](https://detectron2.readthedocs.io/en/latest/modules/data.html)、[PyTorch 参数组学习率](https://docs.pytorch.org/docs/main/optim.html)。本实现增加全图覆盖和分组重复限制，并未安装 Detectron2。

本轮验证范围：源码接口对照、静态语法与差异检查；按用户要求未运行 pytest、训练或推理实验。正式训练的运行稳定性和提分效果尚待用户本机结果确认。
