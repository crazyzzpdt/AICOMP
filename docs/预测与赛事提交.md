## 批量预测与并行读写（2026-09-18）

当前 `predict.py` 已整理为与 `main.py` 相同的 `predict(PredictionConfig(...))` 分节入口；具体实现位于 `三模态预测.py`，D-FINE 批量前向由 `D细化训练.py` 提供。用户选择的 v6 `best.pth` 路径保持不变，不修改训练参数或已有权重。

源码确认原流程为 batch=1，逐张读取三模态、推理、画框、编码、写盘。新流程采用读取线程提前准备输入、主线程整批 GPU 推理、保存线程后台画框写盘；尚未实测各阶段耗时，不能将源码判断当作性能测量结果。

| 入口参数 | 默认值 | 作用 |
|---|---|---|
| batch | 8 | 每批最多 8 组五通道图像，尾批不丢弃 |
| workers / save_workers | 4 / 4 | 读取融合缩放与绘图保存分别并行 |
| prefetch_batches | 3 | 预读窗口最多 24 组，保存队列也最多 24 组；不累计整套解码图 |
| pin_memory | True | D-FINE 当前批次锁页传输，CPU/YOLO 路径不使用此开关 |
| imgsz / 精度 | 1280 / FP32 | 不缩小分辨率，不新增半精度、TF32 加速设置或 INT8 量化 |
| conf / max_det | 0.001 / 100 | 保留原有提交候选口径，不人为抬高弱类分数 |
| png_compression | 1 | PNG 无损低级别压缩，降低编码开销，允许更大图片文件；JPG 不变 |

D-FINE 在 CPU 读取线程中沿用原有等比填充，然后以 uint8 NCHW 批量传输，在 GPU 转为 FP32 并除以 255；单张输入传输量是原先 CPU 浮点输入的四分之一。坐标恢复、EMA、查询类别排序不变。YOLO 按相同原图尺寸分组，保留 `rect=True` 的填充方式；尺寸混杂时实际批次可能小于 8。YOLO 离线 NMS 不设置实时超时截断，避免批次后部图片被跳过。

保存线程只接收 CPU 检测结果，不保留 GPU 张量。全部图片和标签保存成功后才生成正式 ZIP；任何线程异常都会阻止打包，已有目录仍不覆盖。运行结束记录包含读取、推理、绘图、保存的累计秒数与组/秒，以及实际批次大小分布；该时间不包含模型加载与 ZIP 打包。

```powershell
uv run python predict.py --output predict_v6_fast
```

资源由用户根据正式运行情况调整，例如 `--batch 12 --output predict_v6_b12`。没有自动显存探测或隐式减批；显存不足时保留已写结果并提示降低 batch、换新输出目录。默认 8 是未经本机峰值显存实测的配置，不承诺显存占满或固定加速倍数。批量计算可能有浮点微小差异，不保证预测文件逐字节相同，也不承诺提高比赛分数。

本次实施步骤为入口配置整理、两个后端批量化、并行读写与文档同步。仅核对代码引用、实际差异和静态语法；没有新增测试脚本，也没有执行测试、测速、模型推理或训练。

## 结果和提交

```text
predict/
├── images/                  # 原图尺寸的带框 RGB 可视化，同名、同扩展名
├── labels/                  # 每张测试图对应一个同名六列 TXT
├── 比赛提交内容/
│   └── submission.zip       # 初赛只提交这个文件
└── prediction.json          # 本地追溯信息，不放进 ZIP
```

根目录只有三个子文件夹；`prediction.json` 是文件，记录模型 SHA256、运行名、框架版本、样本数和推理参数。

TXT 每行严格为：

```text
class_id norm_center_x norm_center_y norm_w norm_h confidence
```

- 类别沿用赛事顺序 0～11，不重新映射；ball=7。
- 坐标去除缩放和填充后，按原图宽高归一化；不是按 1280 或填充后尺寸归一化。
- 按置信度降序，每图最多 100 个框；无检测生成同名空 TXT。
- ZIP 根目录直接放 TXT，不包含 labels 父目录、图片、权重或 JSON。
- 初赛官方规则要求提交预测结果压缩包；复赛等阶段额外材料需另按当阶段要求准备。

## 历史 YOLO 单张预测配置及依据（当前批量配置见文首）

| 配置 | 当前设置 | 依据 |
|---|---|---|
| 五通道融合 | RGB + IR + Depth | 直接复用 `三模态训练.py`，uint16 深度仍按 20000 mm 截断映射到 0～255 |
| imgsz | 1280 | 与训练验证分辨率一致；没有验证证据时不盲目放大 |
| rect | True | 单张最小矩形填充，保持纵横比，减少空白像素 |
| conf | 0.001 | 与验证候选阈值一致，为 AP 评测保留低分候选 |
| iou | 0.7 | NMS 去重阈值，与比赛的 AP IoU 阈值不同 |
| nms | True | 当前框架显式选择一对多头，与训练验证 nms=None 一致 |
| max_det | 100 | 官方单图预测框上限 |
| quantize | 32 | FP32 推理基线；不沿用训练专用 amp 参数 |
| batch | 1 | 逐张融合与推理，不在内存累计 1000 张五通道图 |
| augment | False | 不引入未经验证的 TTA，不做多模型集成 |
| visual-conf | 0.25 | 仅减少可视化遮挡，不删掉 TXT 中的低分候选 |

因此，图片上的框可能比同名 TXT 行数少，这是两个置信度阈值分工，不是标签错配。

参数基于本项目训练和官方格式设置，并非已验证的全局最优组合。参数和模型比较应使用训练集划分出的验证集，不能人工修改测试集预测来提分。预测脚本的正确性不等于能够保证比赛名次。

## 防覆盖与失败处理

### 后续候选：对齐多标签后处理

安装版本训练验证使用 multi_label=True，当前预测继承默认单标签后处理。可考虑自定义预测器保留同一候选框的多个类别，再执行分类别 NMS；不能向 model.predict 直接增加未支持的 multi_label 配置。此项尚未实施，可能同时增加正确候选和误检，并改变每图前 100 框分配。置信度由用户自行调整，默认仍为 0.001；可视化 F1 最优阈值不能直接当作提交 AP 最优阈值。

已有输出根目录即报错，空目录也不复用；不删除、不追加、不自动混合两次预测。需要重新预测时使用新的 `--output`，例如 `predict_v3`。默认 `predict/`、`predict_*/` 产物被 Git 忽略；使用其他自定义输出名时应补充忽略规则，避免提交运行信息或赛事数据。

任何模态缺失、尺寸不一致、图像损坏、类别不符或非法标签都会中止；不会跳过图片生成表面完整的提交包。中断时已经生成的结果保留，但只有全量预测与逐文件格式检查完成后，才会出现正式 `submission.zip`。打包中断可能留下 `.zip.partial`，它不能提交。

不要在预测进行中修改输入或输出文件。若目录被外部改动导致核验失败，应保留现场，使用新的输出目录重跑，而不是手工补测试集标签。
