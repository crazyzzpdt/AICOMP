## 当前训练

在项目根目录执行：

```powershell
uv run python train1.py
```

这会启动v20诊断，不是已验证提分的新三模态候选：1280、batch4/nbs16、val_batch1，200轮学习率日程、20轮预算。详细配置及对照判断见[v20计划](v19复盘与v20模态诊断.md)。官方三模态数据仍参与配对与增强，但网络仅接收RGB，禁止用此权重生成赛事提交包。

现有datasets无需重建。正式训练中的val=True用于选权重和早停，不因默认禁测而关闭。不自动执行额外测试、语法执行检查、评估、训练或预测；本次未运行这些任务。

恢复仅适用于同源码、同配方、同审计的中断检查点；已完成/预算结束/早停权重不能作为resume继续。更改源码后，旧中断运行应使用其code快照，不绕过指纹校验。

## 2026-09-23 三模态链路静态审计与外部对照

### 实际输入与当前缺口

- train1.py当前architecture=early_v10，MultimodalYOLODataset经fuse_modalities拼接RGB3+IR1+Depth1；EarlyFusionDetectionModel以ch=5构建。首层辅助通道初始权重置零但可训练，不是把IR/Depth输入永久置零。
- predict1.py的历史YOLO和当前融合路径保留五通道；可视化只画RGB不意味着模型只读RGB。v9中RGB切片属于分支结构，IR/Depth另经编码融合。RGBDiagnosticModel确实只读RGB，但仅对应v20诊断。
- predict2.py调用predict1中的DFinePredictor：检查点尺寸/预处理校验，五通道首层、EMA严格加载，五通道批量归一化后前向；不是RGB-only。当前默认v6 best.pth，输出历史产出/复赛_v6。
- **train2.py目前只是官方D-FINE train.py的runpy入口**。官方HGNetv2默认3通道、COCO读图流程；没有在该入口接入历史RGBIRDepth数据集及五通道首层改造。因此它不等于v6/v7历史训练流程，不能按现有示例宣称可直接重训三模态D-FINE。应先补齐专用训练适配及与预测相同的检查点协议，再考虑重训。
- predict2的自动尺寸当前读取DEFAULT_WEIGHTS，早于CLI的--weights解析；切换权重时可能读取错尺寸，并且失败回退1536。现有后端尺寸校验会拒绝不匹配，不能将此解释为已经成功运行却暗中改变输入。临时显式指定正确--imgsz；后续应在解析最终权重后统一读尺寸并明确报错。
- D-FINE与YOLO入口已分开，但predict2仍依赖predict1及项目src包，不是彻底依赖隔离。源码副本不含.git时跳过固定commit核验也是版本可追溯性缺口。
- 同名/同尺寸检查不证明像素级配准或目标语义对齐；本轮静态核查不能替代实际模态消融，更不能证明三模态各自有正贡献。

### CityViMD-Net公开代码与本项目

来源：[模型](https://github.com/KiwiKi12/CityViMD-Net/blob/main/models/model.py)、[配置](https://github.com/KiwiKi12/CityViMD-Net/blob/main/configs/default.yaml)、[数据集](https://github.com/KiwiKi12/CityViMD-Net/blob/main/datasets/multimodal_dataset.py)、[颈部](https://github.com/KiwiKi12/CityViMD-Net/blob/main/models/neck.py)、[提交记录](https://github.com/KiwiKi12/CityViMD-Net/blob/main/SUBMISSION_LOG.md)。依据本轮可见main分支，不代表获分时源码快照。

| 项目 | 对方公开默认实现 | 本项目当前YOLO |
|---|---|---|
| 模型 | 自写CSPDarknet+PAN+YOLOv8风格DFL头；不是官方YOLO26 | 官方YOLO26l迁移、五通道早期融合 |
| 初始化 | 配置pretrained=false，模型卷积Kaiming初始化 | COCO预训练；新增通道可学习 |
| 检测尺度 | PAN实际输出P3/P4/P5，虽然接收P2但没有P2检测头 | 三尺度头，不能将对方优势归为P2 |
| 深度 | uint16裁剪到20000后直接float归一化；最近邻缩放 | 同量程先量化uint8，再/255；存在精度损失，但不是原始毫米直接/255 |
| 红外 | 单通道，含概率0.3的gamma增强 | 单通道，当前不做独立gamma |
| 默认训练 | 640、300轮、batch4、SGD .01、warmup3 | 1280、200轮、batch4、AdamW主5e-5/骨干1e-5、warmup5 |
| 数据读取 | 可见实现仅glob PNG；缺失标签按空目标 | 官方PNG+JPG、严格配对、清洗审计 |
| 后处理 | 单标签分类NMS | 单标签NMS；D-FINE另用原生查询排序 |

对方提交日志自述59.877，并提及增大输入、延长预热、深度修复等；当前默认640配置不能直接认定是59.877获分配方。所检查数据加载文件未见增添外部数据或标签重标流程，但公开源码不足以证明实际历史训练完全没有其他处理。其模型里的模态权重输出是均匀占位，并非学得的门控，不能照搬宣传为自适应融合。

### 下一步优先级

1. 复赛保留已得49.815的v6单模型基线和预测配置；不融合多模型，不以初赛v4分数代替复赛选择。
2. 将train2的五通道训练与predict2协议接通属于优先工程缺口；此轮只审计记录，没有实现或启动新D-FINE训练。
3. YOLO已有v24低学习率候选，按同一清洗/划分与v21比较；不同时再堆分辨率、采样、清洗和新架构，避免无法归因。
4. 若v24仍无提升，考虑独立验证连续浮点深度输入（须训练/预测同时改、重新训练），或只加温和IR gamma的单变量实验；不能在旧权重预测时直接更换归一化。
5. 数据质量需保留真实修改记录，优先复核训练集的配准与漏标；不根据复赛图像人工修框。不承诺上述方法能达到60分。
