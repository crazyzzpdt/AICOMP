# 代码结构与运行

更新：2026-09-23。根目录按YOLO与D-FINE拆为四个业务入口；本轮文档和目录调整不改变v20训练配方。

## 模块职责

| 文件 | 职责 |
|---|---|
| train1.py | YOLO训练入口；当前v20 RGB诊断入口 |
| train2.py | D-FINE训练入口，转发`src/D-FINE/train.py` |
| predict1.py | YOLO预测、后处理、结果ZIP及材料导出 |
| predict2.py | D-FINE预测入口 |
| src/yolo/aic/ | YOLO模型、数据集、训练器和几何处理 |
| src/D-FINE/ | D-FINE模型、训练器和部署工具 |
| tools/prepare_dataset.py | 有记录的数据准备与清洗；不在日常训练前反复运行 |

历史中文模块已迁移，不应重新创建中转入口。历史源码、依赖和文件名见[旧运行合订本](归档/05_旧运行与环境记录.md)。

## 当前训练

在项目根目录执行：

```powershell
uv run python train1.py
```

这会启动v20诊断，不是已验证提分的新三模态候选：1280、batch4/nbs16、val_batch1，200轮学习率日程、20轮预算。详细配置及对照判断见[v20计划](v19复盘与v20模态诊断.md)。官方三模态数据仍参与配对与增强，但网络仅接收RGB，禁止用此权重生成赛事提交包。

现有datasets无需重建。正式训练中的val=True用于选权重和早停，不因默认禁测而关闭。不自动执行额外测试、语法执行检查、评估、训练或预测；本次未运行这些任务。

恢复仅适用于同源码、同配方、同审计的中断检查点；已完成/预算结束/早停权重不能作为resume继续。更改源码后，旧中断运行应使用其code快照，不绕过指纹校验。

## 预测与材料

YOLO当前选择v5 best.pt，数据源为“datasets/test”，输出为“历史产出/复赛predict_v5”；D-FINE使用predict2.py。更换候选必须显式指定权重；不自动选择最近训练目录，不默认提交v20。完整命令见[预测与赛事提交](预测与赛事提交.md)。

预测后打包采用所选权重运行的训练快照，而不是当前main.py；若历史快照缺失则记录待补，不冒充训练复现完整。提供实际使用的Ultralytics源码副本与依赖版本，因为仅记录pip版本不足以复现项目修改。

## 数据与Git边界

datasets为训练工作数据，`datasets/test`为复赛测试源；“数据集”为官方来源；runs为训练产物。预测结果统一写入历史产出，模型、赛事图像、标签、预测包、训练产物和原始PDF均不上传GitHub。
